## Question 2: How does Atlas handle intent recognition?

### Answer

Atlas intent recognition is the process by which the Atlas reasoning engine classifies a user's message into one or more predefined intents. This is the first critical step in the Agentforce execution flow, as it determines which Topics are activated and what Actions are considered.

### Architecture Explanation

**Intent Recognition Process**

1. **Message Preprocessing**
   - The user's message is received and preprocessed
   - Punctuation, special characters, and noise are normalized
   - The message is tokenized for LLM consumption
   - Language detection is performed if multilingual support is configured

2. **Context Enrichment**
   - The message is enriched with conversation history (last N turns)
   - User profile data is appended (if available)
   - Session state variables are included
   - Previous Topic context is included

3. **LLM-Based Classification**
   - The enriched message is sent to the LLM with a classification prompt
   - The prompt instructs the LLM to classify the message against all configured Topics
   - The LLM returns a ranked list of Topic matches with confidence scores
   - The classification prompt includes examples of intent patterns for each Topic

4. **Confidence Thresholding**
   - Each Topic match is assigned a confidence score (0-1)
   - A configurable confidence threshold determines the minimum score for activation
   - Topics above the threshold are activated
   - Topics below the threshold are not activated

5. **Multi-Intent Handling**
   - If multiple Topics exceed the threshold, all are activated
   - Atlas prioritizes Topics based on confidence scores
   - The highest-confidence Topic becomes the primary Topic
   - Secondary Topics are addressed after the primary Topic is resolved

6. **Fallback Handling**
   - If no Topic exceeds the threshold, Atlas triggers a clarification question
   - The clarification question is generated by the LLM based on the unclassified message
   - If the user's response still doesn't match any Topic, Atlas falls back to a default Topic
   - The default Topic typically provides general assistance or escalates to a human agent

**Intent Recognition Configuration**
- Topics include example phrases that Atlas uses for classification
- Topic descriptions guide the LLM's understanding of each intent
- Topic instructions define the behavior when a Topic is activated
- Confidence thresholds can be configured per Topic or globally

### Real-World Example

A customer sends: "My package hasn't arrived and I want to complain about the delay."

Atlas intent recognition:
1. **Preprocessing**: Message is normalized (punctuation removed, tokenized)
2. **Context Enrichment**: User's previous conversations about shipping are included
3. **LLM Classification**: Classifies as "order status" (88%) and "complaint" (72%)
4. **Thresholding**: Both exceed the 60% threshold, so both Topics are activated
5. **Prioritization**: "Order status" is primary (88%), "complaint" is secondary (72%)
6. **Execution**: Atlas first addresses the order status (retrieves tracking info), then addresses the complaint (creates a case and offers compensation)

### Common Mistakes

- Not providing enough example phrases for each Topic, leading to poor classification
- Setting the confidence threshold too high (misses valid intents) or too low (activates wrong Topics)
- Not handling multi-intent requests properly
- Ignoring the fallback mechanism for unrecognized intents

### Interview Tips

- Explain the full intent recognition pipeline from preprocessing to fallback
- Emphasize the role of Topic descriptions and example phrases
- Discuss confidence threshold configuration and its impact
- Mention multi-intent handling as a key differentiator

## Question 2: How does conversation context work?

### Answer

Conversation context is the information from previous turns in the conversation that provides continuity and relevance to the current interaction. Managing conversation context is essential for building natural, coherent multi-turn conversations.

### Architecture Explanation

**Conversation Context Components**

1. **Turn History**
   - Previous user messages and agent responses
   - Typically the last N turns are retained
   - Configurable window size (e.g., last 5 turns)
   - Older turns are archived or discarded

2. **Intent History**
   - Intents recognized in previous turns
   - Helps maintain topic continuity
   - Example: "Previous intent: order status inquiry"

3. **Action History**
   - Actions executed in previous turns
   - Helps avoid redundant actions
   - Example: "Previous action: GetOrderStatus already executed"

4. **Topic History**
   - Topics activated in previous turns
   - Helps with Topic switching and continuity
   - Example: "Previous Topic: Order Management"

5. **User Intent History**
   - The user's evolving goals across turns
   - Helps the agent understand the overall conversation purpose
   - Example: "User's goal: resolve a billing issue"

**Conversation Context Management**

1. **Context Window**
   - The number of previous turns included in context
   - Larger windows provide more context but consume more tokens
   - Default: last 5 turns
   - Configurable per agent

2. **Context Summarization**
   - Long conversations are summarized to reduce token usage
   - Summaries capture key information from previous turns
   - Summaries are generated by the LLM

3. **Context Prioritization**
   - More recent turns are given higher priority
   - Relevant turns are given higher priority
   - Irrelevant turns are deprioritized or excluded

4. **Context Clearing**
   - Context is cleared when the conversation ends
   - Context can be cleared manually for new topics
   - Context timeout clears stale context

**Context Injection**

- Conversation context is injected into the prompt
- Context is formatted for LLM consumption
- Context is included as part of the grounding data
- Context is available to the Atlas engine for decision-making

### Real-World Example

A multi-turn conversation about a return:

Turn 1: "I want to return my order"
- Context: Intent = "return request", Topic = "Returns"

Turn 2: "It's order #12345"
- Context: Intent = "return request", Topic = "Returns", OrderNumber = "12345"

Turn 3: "When will I get the refund?"
- Context: Intent = "return request", Topic = "Returns", OrderNumber = "12345", UserGoal = "refund timeline"
- The agent retrieves the return status and refund timeline based on the accumulated context

Turn 4: "Actually, I want to exchange instead"
- Context: Intent = "return request" → "exchange request", Topic = "Returns" → "Exchanges"
- The agent switches Topics based on the updated user intent

### Common Mistakes

- Not maintaining sufficient conversation history
- Not summarizing long conversations
- Not prioritizing relevant context
- Not clearing stale context
